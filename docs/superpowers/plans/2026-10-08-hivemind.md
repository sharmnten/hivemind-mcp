# Mio Hivemind Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for inline implementation. The user authorized sensible decisions and continued implementation without proposal-only handoffs.

**Goal:** Build Supabase-backed project-only shared memory with no AI API key.
**Architecture:** Shared validation and privacy rules protect a Node MCP/API service and enrolled-workspace hooks. Transactional PostgreSQL RPCs enforce current brain membership and concurrency. React provides authenticated administration.
**Tech Stack:** Strict TypeScript, Node 24, official MCP SDK, Supabase Auth/Postgres, pg_trgm, Zod, React, Vitest.
**Spec:** `docs/architecture.md`

## Global Constraints

- No AI provider calls or embedding generation.
- Do not persist or log raw conversation context.
- Supabase is the production backend; local PostgreSQL is for verification only.
- No cloud provisioning, paid requests or public deployments without permission.
- Brains require explicit membership; Studio Global has no inherited access.

## Review Focus

- Direct RPC calls must not bypass privacy validation or elevate verification.
- Queue idempotency must detect changed payloads and never cross actor/brain boundaries.
- Hook enrollment must reject symlinked note/config files and nested unapproved workspace roots.
- Brain switching must not expose previous cached data or retain stale role state.
- Deleting a memory must purge revisions, source data and linked handoffs.
